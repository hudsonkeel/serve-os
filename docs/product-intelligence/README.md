# Serve OS Product Intelligence

**Status:** Placeholder — nothing built yet. This document exists to preserve
a decision, not to describe a system that exists today.

## What this will become

Serve OS Product Intelligence will become the canonical product memory for
Serve OS itself — ideas, problems, opportunities, decisions, partnerships,
release learnings, and deferred work, all in one durable place instead of
scattered across conversations, commit messages, and someone's memory.

## Two operating principles, held in tension on purpose

- **Capture should be effortless.** Nothing worth remembering should be lost
  because writing it down was inconvenient in the moment.
- **Implementation should remain disciplined.** Effortless capture does not
  mean undisciplined construction — this system will follow the same
  deterministic-before-AI, evidence-and-provenance, human-judgment-remains-
  authoritative principles already governing the rest of Serve OS (see
  `DECISION_LOG.md`'s Phase 2 entry and `docs/intelligence/SERVE_INTELLIGENCE_CONSTITUTION.md`).

## What's here today

Just an inbox. [`CAPTURE_INBOX.md`](./CAPTURE_INBOX.md) holds the current
known follow-up items in one-line form — nothing more. No schema, no engine,
no UI.

## What's next

The complete operating system — how items move from captured to triaged to
acted on, what a "decision" record looks like versus an "idea," how this
relates to `DECISION_LOG.md` and the existing intelligence architecture
docs — will be designed in a future, bounded phase. This document is not
that design. Do not build against it.
